# 许可证与商业授权

## 一、项目许可证

「小熊猫 · Red Panda」以 **GNU Affero General Public License v3.0 only
（AGPL-3.0-only）** 发布。完整条款见仓库根目录的 [LICENSE](../LICENSE)。

选择 AGPL-3.0 的原因：

- 它是 OSI 认可的开源许可证，开发者和公司都熟悉，利于社区贡献；
- 它有强 copyleft 效力：任何人修改后通过网络提供服务，必须向用户提供修改后的源码；
- 维护者保留版权，可以同时提供**商业授权**，支撑项目的长期维护。

## 二、你可以做什么

在**遵守 AGPL-3.0** 的前提下，你可以：

- ✅ 个人使用、学习、研究；
- ✅ 修改代码并自行部署；
- ✅ 分发原版或修改版；
- ✅ 商用（包括收费产品、托管服务），**但必须满足下面的义务**。

## 三、你必须做什么

AGPL-3.0 的核心义务：

1. **开源修改**：你分发修改版，或以修改版通过网络向用户提供服务时，必须以
   AGPL-3.0 提供完整的对应源码（Corresponding Source）。
2. **保留声明**：保留版权声明、许可证文本和免责声明，标明你做了哪些修改。
3. **网络服务条款（§13）**：如果你把修改版作为网络服务提供，必须让用户能够
   获取该版本的源码。
4. **不得附加限制**：不能对下游用户施加比 AGPL-3.0 更严格的附加条款。

> 简单说：**用了 AGPL 代码，就要把源码按 AGPL 交出去**。不愿意交源码的场景，
> 就需要商业授权。

## 五、贡献代码与 CLA

### 为什么需要 CLA

本项目采用 **AGPL-3.0 + 商业授权** 的双许可模式。为了让维护者能够把社区贡献
也纳入商业授权，需要贡献者签署 [CLA](../CLA.md)（贡献者许可协议）。

没有 CLA 时，贡献者对其提交的代码仍保有完整版权，维护者无法单方面将这些代码
用于商业许可或更换许可证。

### CLA 授予了什么

- 你**保留**自己贡献的版权；
- 你授予维护者永久、全球、非排他、免版税、不可撤销的版权许可，
  包括**再许可/重新许可**（含商业许可）的权利；
- 同时授予必要的专利许可。

CLA 不是版权转让（copyright assignment），你仍然可以自由使用自己的贡献。

### 如何签署

1. 提交 Pull Request；
2. CLA Assistant 机器人会评论提示；
3. 在 PR 中回复：

   ```
   I have read the CLA Document and I hereby sign the CLA
   ```

4. 机器人记录签名，之后你的所有贡献都适用。

签名保存在 `cla-signatures` 分支的 `signatures/version1/cla.json`。

### 维护者需要做的配置

工作流位于 [`.github/workflows/cla.yml`](../.github/workflows/cla.yml)。首次启用：

1. 仓库 **Settings → Secrets and variables → Actions → New repository secret**；
2. 新增 `CLA_ASSISTANT_PAT`，值为一个具有以下权限的 fine-grained PAT
   （或经典 PAT 的 `repo` 权限）：
   - Contents: Read and write
   - Pull requests: Read and write
   - Actions: Read and write
   - Commit statuses: Read and write
3. 确保 **Actions** 已启用。

> 也可以改用托管服务 [cla-assistant.io](https://cla-assistant.io/)，安装 GitHub App
> 后无需维护工作流和 PAT。

## 七、常见问题

**Q：我可以把它用于公司内部工具吗？**
A：如果只是组织内部使用、不对外分发、也不让外部用户通过网络访问，通常不触发
AGPL 的分发/网络条款。但一旦对外提供服务或分发，就需要履行 AGPL 义务。
合规要求严格的团队建议直接购买商业授权。

**Q：我可以拿它做 SaaS 赚钱吗？**
A：可以，前提是遵守 AGPL-3.0：向用户提供你修改后的完整源码。如果你不愿意开源
修改，请购买商业授权。

**Q：为什么不用 MIT？**
A：MIT 允许别人闭源商用且无需回馈，无法支撑「维护者靠商业授权获利、同时鼓励
贡献」的目标。

**Q：贡献之后我还拥有自己的代码吗？**
A：拥有。CLA 是许可授权，不是版权转让。

**Q：AGPL 会影响我的其他代码吗？**
A：AGPL 的 copyleft 只作用于本项目及其衍生作品。通过进程边界、网络 API 等方式
独立调用的程序通常不视为衍生作品，但具体边界建议咨询律师。

**Q：项目提供担保吗？**
A：不提供。软件按“现状”提供，详见 LICENSE 中的免责条款。
